2. What Happens When You Upload a Photo

ClearPix is a cross-platform web application usable on modern web browsers across Android smartphones, iPhones, iPads, Windows PCs, macOS computers, and Linux workstations.

When you select or drag a photo into the ClearPix workspace and click Enhance Photo:

  1. Encrypted HTTPS Transmission: Your image file is streamed directly from your browser to the ClearPix server API endpoint (/api/enhance) over TLS/HTTPS encryption.
  2. In-Memory Validation: The server receives the raw byte stream directly into volatile memory (RAM). Pillow validates magic-byte image signatures (verifying genuine JPG, PNG, or WebP headers), checks dimensions (minimum 16×16 px, maximum 4096×4096 px), enforces a 25 MB file size limit, and transposes EXIF orientation metadata so your photo is never sideways.
  3. Server-Side AI Inference: The decoded RGB/RGBA tensor is passed to our self-hosted Real-ESRGAN x4plus neural network. Processing executes server-side utilizing available hardware accelerators (such as GPU tensor acceleration or CPU threads). Processing does not execute inside the client browser’s local JavaScript sandbox.
  4. Output Generation: The neural network synthesizes high-frequency textures at 2× or 4× resolution. The enhanced result is encoded as a lossless PNG image.

3. Where Files Are Stored & The 1-Hour Automatic Deletion Lifecycle

ClearPix is specifically designed to minimize data persistence. We practice data minimization by default:

Original Uploads

Original photos are held in volatile system memory (RAM) solely for the duration of inference. The raw original file is not saved to persistent disk storage.

Enhanced Outputs

Enhanced PNG files are saved in an internal, non-public temporary directory (temp/outputs/{result_id}.png). Each image is assigned a cryptographically random 32-character hexadecimal UUID (e.g., b7f2a89...) that cannot be enumerated.

Strict 1-Hour Automated Cleanup Policy

Every temporary enhanced image is assigned an automatic expiration timestamp of 3,600 seconds (1 hour). On every enhancement request and through periodic background sweeps, the automated lifecycle manager (TempFileManager.cleanup_expired()) deletes all files older than 1 hour from the server disk. No residual files, backups, or shadow copies are retained.

4. Zero Third-Party Sharing & No AI Model Training

We believe your personal photos belong to you alone. We commit unconditionally to the following:

  • No Model Training: Uploaded images and enhanced outputs are never used to train, re-train, fine-tune, or evaluate machine-learning models.
  • No Cloud Vision Brokers: ClearPix does not use third-party computer-vision APIs, commercial cloud processors, or foreign inference proxies (such as OpenAI, Google Cloud Vision, or AWS Rekognition). All neural execution is hosted directly on ClearPix infrastructure.
  • No Data Brokers or Advertisers: We never sell, rent, monetize, or disclose uploaded photos or metadata to data brokers, marketing companies, or analytics networks.

5. Cookies, Local Storage & Server Logging

ClearPix maintains a clean, tracking-free web architecture:

  • No Tracking Cookies: We do not set tracking cookies, session cookies, marketing pixels, or third-party advertising identifiers.
  • Browser LocalStorage: The web interface stores exactly one item in your local browser storage: clearpix-theme (set to "dark" or "light"). This purely persists your preferred visual contrast across page visits and never leaves your browser.
  • Server Diagnostic Logs: Standard HTTP server logs record request timestamps, HTTP request paths (e.g., POST /api/enhance), HTTP status codes, and execution duration. These logs are used solely for real-time error diagnostics and concurrency rate-limiting. Logs do not store image content.

6. Security Safeguards & Honest Limitations

ClearPix implements defensive engineering safeguards at each tier:

  • Cryptographic Filenames: All temporary outputs use non-sequential, randomly generated 32-character hex UUIDs to prevent unauthorized URL guessing or directory enumeration.
  • Input Validation & DecompressionBomb Guard: File headers are inspected to verify genuine JPEG, PNG, or WebP bytes. Maximum dimensions are strictly capped at 4096×4096 px and 16 MP, with Pillow's internal bomb protection set to 32 MP to prevent memory-exhaustion exploits.
  • Path Traversal Prevention: Download filenames are sanitized with strict regular expressions (re.sub(r"[^\w\-.]", "_", ...)), stripping directory traversal sequences (../) and null-byte injections.
  • Concurrency Semaphores: Server concurrency is protected by bounded semaphores to avoid memory contention and system thrashing.

Security Limitations: While we implement robust defenses, no system connected to the Internet can guarantee absolute security. Users should not upload sensitive government-classified documents, medical records, or personally identifiable data requiring specialized regulatory compliance (such as HIPAA).
